# 1.0.4：共看连续用梗的上下文修复

## 改动

- 把“读取最近一次 Planner 留下的聊天快照”改成“每条 Replyer 请求重新读取当前真实会话最新收发消息，并带入宿主已提供的当前任务、媒体和事实资料”。召回候选仍可缓存，不增加逐条向量调用。
- 把“同一会话共用一份回复决策”改成“按真实 session_id 与 reply_message_id 保存该条回复的决策和上下文”。质量门与异步效果评估使用这一份快照，评估完成后消费掉记录；不存在对应记录时不借用其他回复或后续 Planner 的状态。
- 把“不得因为担心复读而拒绝用梗”改成“先核对当前任务与最近已发送回复；用户指出重复或要求停止、最近已使用明显梗时优先 SKIP，明确要求引用或重复除外”。旧视频和助手自己说过的梗不能充当当前场景的新触发证据。

这只修改梗插件的上下文传递、许可判断和评估归属，不修改宿主的全局路由、Timing Gate、Planner / Replyer 顺序或基础角色 Prompt；不封禁某个词，不增加计时冷却或重试。插件现有可识别用梗风格、卡片语义及资源包保持不变。此插件仅提供 zh-CN，未新增其他语言模板。

## 基线与根因复核

正式后端基线为 `f72e7ba50a2d76fa421e0a9d960346f6e2b53091`，插件基线为 `d25e4b5c7380e8aa121096761653a2dfe53f3313`。任务从最新插件 origin/main `288dc7b303cd006f353a1555afcb79e62c157c09` 开始，并先快进到包含正式已发布资源的 d25e4b5，避免丢失生产梗库。

原始线上问题的 8 次选梗请求使用同一个旧聊天快照，当前机场素材只出现在 Replyer 输入中。首次只修复上下文的版本虽通过状态测试，但真实模型在后段机场场景仍返回 USE；该版已经撤回。进一步核对发现本插件选择器明确要求不要因担心复读而拒绝，是第二个可定位的原因。随后固定相同的最新上下文，只调整这一条选择合同进行对照，负向场景才全部跳过。

最后版本合并了已证实需要的当前上下文传递和选择合同修正；不是继续在失败方案上增加冷却、关键词屏蔽或延迟。
